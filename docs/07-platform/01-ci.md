# CI

`.github/workflows/staging-orchestrator.yml` runs on PRs to `main` and manual dispatch. It calls `scripts/orchestrator/detect-affected.mjs --pr` and `map-affected-to-workflows.mjs`, using the target mapping under `scripts/orchestrator`, to select reusable jobs.

| Selected surface | Reusable workflow |
| --- | --- |
| Next.js apps | `staging-w-app-nextjs.yml`, matrix of affected targets and `local` / `vercel` deployment targets |
| Web Docs | `staging-w-tool-web-docs-client.yml` |
| Storybook | `staging-w-tool-storybook.yml` |

The orchestrator also runs all-monorepo validation independently of affected target selection. `ci-setup-node` installs pinned pnpm/Node, restores caches and uses `pnpm install --frozen-lockfile`. `ci-validate-all-monorepo` and `ci-validate-monorepo-package` centralize validation. [Testing](../06-quality/01-testing.md) owns the test strategy.

Concurrency cancels earlier runs for the same PR. The automatic diagram commit job is commented out. App staging jobs can post preview comments and send notifications; workflows explicitly scope permissions.

This page records current YAML behavior. Branch-required checks, app installation permissions and GitHub environment approvals require [manual verification](../10-services/01-github.md). Production path filters and workflow deduplication are follow-up concerns, not changes in this documentation foundation.

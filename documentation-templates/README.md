# Documentation authoring templates

These files are authoring aids outside the published docs tree. Copy the relevant template to its canonical location under `docs/`, replace prompts with verified Kartuli-specific content, and remove inapplicable headings. Do not publish empty placeholders. Do not copy shared policies into every page: link their canonical owner.

Use technology-library.md for a dependency with recurring project conventions, service.md for external integration details, quality.md for a validation capability and runbook.md for a repeatable operation. Status is implemented, planned, evaluating or deprecated; intent is specification, architecture, runbook or reference. Every page needs a nonempty one-line description and an H1 suitable for navigation.

Name source/config evidence, separate requirements from observations, and mark unknown provider state as manual verification required. Validate with the Web Docs commands and the full repository gate. See docs/12-project/01-documentation/01-writing-guide.md.
